核查日期：2026-10-17。检查了用户提供的 [JoyMaas 模型广场](https://joymaas.jd.com/models)、其公开目录接口和 JoyAI-VL-Interaction 官方说明/调用示例。公开目录返回 41 项；可复核的筛选字段保存在 [目录快照](joymaas-catalog-2026-10-17.json)。目录初次核查时没有密钥；后续用户已配置凭证并进行了真实调用，最新结果见 [真实调用报告](joymaas-live-test-2026-10-17.md)。

## 京东模型适合放在哪一层

| 模型 | 当前目录列出的输入/输出 | 在本项目中的位置 |
| --- | --- | --- |
| Qwen3.6-35B-A3B | 文本/图像/视频 → 文本，已发布 | 可优先试验结构化动作指导与画面解释；真实延迟、引用质量和输出协议仍待凭证实测 |
| JoyAI-VL-Interaction | 文本/图像 → 文本，已发布 | 可试验视觉交互与短提示；官方介绍强调流式视频，但当前 MaaS 目录仅标文本/图像，不能据此承诺该托管 API 已开放完整视频流能力 |
| GLM-4.6V | 文本/图像/视频/文件 → 文本，已发布 | 视觉复核、关键帧解释候选 |
| Qwen3-8B 等文本模型 | 文本 → 文本 | 不适用于现在网页发送双图的看图指导流程 |
| 图像/视频生成模型 | 生成图像或视频 | 不用于测量关节或岩点掩膜 |

本次公开目录未发现 ViTPose、RTMPose、SAM 系列，或专门返回人体关键点/掩膜/持续目标 ID 的服务。多模态大模型可以用于解释几何观测，但目录中支持“图像理解”不等于精确关键点估计或像素分割接口，不能直接替换当前测量层。

JoyAI 原始说明：[模型介绍](https://joybuilder.s3.cn-north-1.jdcloud-oss.com/llm-model/std-JoyAI-VL-Interaction_readme.md)、[官方调用示例](https://aiagent.s3.cn-north-1.jdcloud-oss.com/llm-model/std-JoyAI-VL-Interaction_demo.md)。其示例使用 `https://modelservice.jdcloud.com/v1/chat/completions` 和 Bearer API Key。账号实际可调用型号以服务端为准，公开目录不等于已获得调用权限。

## 已实现的指导链路

`同帧原图 + 岩点编号图 + 当前姿态 + 已确认候选岩点 + 短时运动状态 + 本次核对的支点 + 用户提示词 → 技术知识检索 → Qwen3.6 → 校验一个结构化动作 → 眼镜短句与网页详版`

在 `/pose` 的“下一步指导”区域同时显示：

- **眼镜版**：一个动作，最长 20 个 Unicode 字符；例如“看 #3，确认下一点”或条件满足时的“左脚试探 #5”。没有把后者预设为当前视频的真实建议。
- **网页端**：与眼镜端相同的第一条指令、选择理由、引用的当前观测、知识引用、限制和执行前条件。
- **来源标签**：明确区分“本地策略预览”和“大模型生成”。未配置凭证时不会伪装成 AI 实际输出；本地策略只做观察/确认，不自动决定换点。
- **提示词**：页面可编辑“我的指导提示词”（保存在本浏览器，最多 3000 字），补充脚法、髋部、语言风格偏好。固定输出约束可展开查看，源文件是 [climbing-coach-v1.md](prompts/climbing-coach-v1.md)，服务端实际读取同一文件。
- **指令 JSON**：可导出 `climbcue.glasses.v1` 数据包，包含文字、目标编号、原画面坐标、帧号、模式和有效期。当前是眼镜显示预览，未接入真实眼镜硬件；画面坐标不是眼镜的三维锚点。

## 为什么让模型选结构化动作

大模型只选择 `inspect_hold / confirm_support / test_move / wait_observation`、肢体、目标编号和解释。短句由程序统一生成，因此不会出现网页说“左脚”而眼镜说“右脚”的压缩错误。未知岩点、无效引用、超出允许候选的动作和不符合 JSON 契约的输出直接拒绝，不下发猜测性文本。

`test_move` 的候选条件：固定机位、唯一检测对象、肩髋可见、足够连续帧、低位移状态、其他三个支点由用户本次确认且与可见肢体邻近；目标不在当前支点中，并通过二维肢段距离筛选。17 点模型缺少脚尖时不会补造脚部数据。该筛选只是原型门槛，未经教练标注校准，不证明真实可达、摩擦或承重。

当前支点选择放在折叠区。实时确认在 15 秒后或末端位置明显变化后失效；暂停帧可以保留用于离线检查。眼镜目标编号需要参照同一帧的标记；真实眼镜部署还需要相机标定、坐标配准与硬件 SDK。

## 时效与用户操作

- 手动“截取瞬间并分析”为默认：自动暂停并锁定同帧图片/姿态/已确认分割轮廓，关闭自动更新；仍可主动选择每 6 秒更新。选择大模型后，自动更新会产生对应模型调用。
- 实时结果自请求观测起最多有效 5 秒；计算完成时已经过期、人物明显移动、关键点丢失、恢复播放、切换输入/模型或岩点改变，旧结果撤回。
- 暂停帧结果明确标注“暂停帧预览”，不冒充实时指令。
- 这些门槛不是经验证的运动安全系统；当前测试只证明接口、显示和拦截规则按设计工作，没有教练真值评估或现场眼镜验证。当前使用固定机位视频；若未来直接使用随头部移动的眼镜摄像头，需要先解决相机运动补偿与场景配准。

## 配置真实指导模型

默认接入用户给出的 `POST https://modelservice.jdcloud.com/v1/chat/completions`，模型 `Qwen3.6-35B-A3B`。请求包含 Bearer 鉴权、每次独立 UUID 的 `Trace-Id`、`stream:false`。官方入口：[Qwen3.6 API](https://joymaas.jd.com/models/Qwen3.6-35B-A3B#api)。

在项目根目录 `.env` 填写：

```dotenv
CLIMBCUE_COACH_BASE_URL=https://modelservice.jdcloud.com/v1
CLIMBCUE_COACH_MODEL=Qwen3.6-35B-A3B
CLIMBCUE_COACH_API_KEY=填写你自己的密钥
```

`.env` 已加入 Git 忽略，密钥仅由本机服务端读取。指导模块每次请求重新读取配置，保存后无需重启；环境变量优先。支持普通 KEY=value、引号和注释，不执行 shell、不展开变量。仅指导模块读取 `.env`；知识库的独立 LLM 配置仍通过环境变量配置。

网页打开 `/pose`，在“下一步指导”点“测试模型连接”：发出一条小文本请求和一条纯蓝色图片识别请求，显示每项实际响应与耗时。通过后自动选“大模型生成”。此测试会消耗账号额度，验证的是基本接口与简单视觉任务，不是攀岩准确率。

再选择测试视频，暂停，标记岩点，填写提示词，点击“分析当前姿态”。前端从同一个已渲染的姿态帧同步生成原图与编号图（JPEG，最长边 960 px），不从正在前进的视频重新截帧，预览镜像不会镜像上传画面。服务端校验快照 ID、图像格式、尺寸和画幅比例。人体点坐标及可见度、岩点来源/颜色、已确认支点、短时运动状态和 RAG 片段作为文本同时发送；图片使用 `content` 中的 `image_url` + base64 data URL。该格式已通过本地协议测试，也曾成功返回真实图片理解与攀岩指导；账号实名认证仍有间歇拒绝，详见真实调用报告。

请求超时 45 秒，前端等待上限 55 秒。实时场景自原观测起超过 5 秒仍丢弃，未延长旧指令有效期；先使用暂停帧检查完整结果，再用真实端到端延迟评估实时可用性。JSON/引用/动作校验失败、401/403/429 或超时都有清晰提示，不把失败降级伪装成云模型成功。

命令行真实测试（最多两次连接请求＋一次攀岩请求）：

```bash
# 先生成实际视频帧测试输入；此步骤模拟云端返回，不消耗模型额度
npm run test:coach-vision
# 密钥配好后，实际调用选定模型
.venv/bin/python scripts/test-joymaas.py --input artifacts/coach-vision-input.json
```

测试输入的手动标记用于验证协议，不是教练标注的真实支点。报告保存在 `artifacts/joymaas-live-report.json`，不包含 API Key；图片输入仅保存在本机忽略提交的 artifacts 目录。

## 前端可视化结果区（2026-10-17）

已配置凭证时默认选“大模型生成”，用户仍可切回本地预览。点击“截取瞬间并分析”冻结快照，显示分析中状态和计时；成功后滚动到结果区。

- **对照画面**：使用本次请求保存的原始图像，切换姿态/岩点叠加。绿色为骨架、蓝色为确认的候选轮廓、黄色为模型选中的肢体或目标；只在校验通过的试探动作有明确起止点时画箭头，不给确认动作虚构目标。
- **简略版**：眼镜样式的一句话提示、动作类型和快照状态。
- **详细版**：同一动作标题、为何选择、执行条件、观测依据、尚需确认与参考知识。
- **验证信息**：实际模型名、耗时、帧号与视频时间；可展开本次返回数据（不含凭证）。失败和过期状态明确显示，恢复播放或切换输入会清除旧指导与旧快照。

实际测试用视频姿态和两处 MobileSAM 分割，一次云端返回用时 1716.2 ms，简短版“先确认左手支撑”。已检查原图/叠加切换、返回 JSON 与画面帧号一致、桌面与 390px 手机布局。此为一次真实链路测试，不代表模型指导质量已由教练验证。

截图：`artifacts/coach-snapshot-card.png`、`artifacts/coach-snapshot-card-mobile.png`；报告：`artifacts/coach-snapshot-live-report.json`。`npm run test:coach` 使用本地预览验证恢复播放、过期返回与切换输入的撤回。


### 岩点显示修复

对照快照现在独立提供“显示姿态”“显示岩点”。岩点轮廓加粗并加深色描边，编号按实际显示尺寸保持 14px，竖屏缩略图不再把编号缩成几像素。下方列出本次全部岩点，可点击编号恢复图层并突出显示（只查看，不产生新指导），支持“放大查看”。没有确认岩点时明确提示。

分析入口显示已确认与已选候选数量。有选中候选时，按钮明确为“确认 N 个所选候选并分析”，点击会把这些候选确认后一起送入本次快照；不会静默忽略候选或把未选中的候选加入指导。分割处理中暂不允许分析。

实际视频＋本机颜色分割回归：9 个轮廓与编号进入请求并显示；关闭/恢复岩点图层的像素变化、编号列表、放大图和手机布局均通过。测试只用本地预览，不消耗云模型额度。命令 `npm run test:hold-visibility`，报告 `artifacts/hold-visibility-report.json`，大图 `artifacts/hold-visibility-large.png`。
