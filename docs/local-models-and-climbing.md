# M2 本地模型与攀岩指标

核对与实测日期：2026-10-17。机器：Apple M2，16 GiB 统一内存，8 核 CPU。

> 更新：已扩展为 6 种姿态模型、3 种分割模型，并增加双端指导预览；见 [新增模型实测](model-benchmark-m2.md) 和 [指导设计](joymaas-and-coach.md)。下文 Lite / Full 性能为第一轮较长采样测试。

## 当前可用方案

网页 `/pose` 已接入 MediaPipe Pose Landmarker **Lite / Full** 两个本地模型，均输出 33 个关键点。模型在浏览器 Worker 内以 CPU / WebAssembly 运行，所有依赖、权重由本机提供，不向外部服务发送视频。默认 Lite，目标帧率可选 30 / 15；这是调度上限，实际速度由推理、解码与绘制共同决定。切换模型会停止当前输入、清空本次数据，再选择输入即可运行。

使用项目的两段 720 × 1280 视频，在 Chrome headless 中完整运行网页；推理输入长边上限 960 像素。每个模型/视频跳过前 20 个结果，采集后续 90 个结果，FPS 由结果到达的实际时间间隔计算。

| 模型 | 视频 | 推理中位数 | 推理 P95 | 处理 FPS |
| --- | --- | --- | --- | --- |
| Lite | 1 | 30.6 ms | 41.3 ms | 24.31 |
| Lite | 2 | 30.8 ms | 34.8 ms | 26.30 |
| Full | 1 | 45.1 ms | 46.2 ms | 19.82 |
| Full | 2 | 45.6 ms | 49.7 ms | 18.87 |

因此保留 Lite 作为实时默认，Full 供同一视频对照。这里没有带标注的攀岩姿态真值，不能声称 Full 在本项目更准确；可见点数量也不是准确率。测试未覆盖实体摄像头精度、Safari、长时间发热降频或并发重负载；FPS 会随场景及系统负载变化。

模型文件：Lite 5,777,746 bytes；Full 9,398,198 bytes。`scripts/setup-pose.mjs` 固定 float16 / version 1 的下载地址和 SHA256，并生成本地 manifest。Google 官方提供 Lite、Full、Heavy 三种包，本次只下载和验证了前两种。[官方模型文档](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)

## ViTPose+ Large 和 SAM3.1 是否能在本机跑

- 项目原有 `vision-demos-main/rock_climbing` 通过 **VLM Run 网关**调用两模型，本地只做视频处理、相机配准及结果绘制。该流程需要 API Key 和云端计费，尚未实际验证完整调用。
- ViTPose+ Large 可以作为单独的本地部署实验候选。Hugging Face 提供 ViTPose 模型实现；PyTorch 的 MPS 后端能利用 Mac GPU，但框架支持 MPS **不等于该模型、人员检测器和整条视频流程已经在本机兼容或达到实时**。当前未安装/实测这条流程，不提供虚构 FPS 或内存保证。[ViTPose 文档](https://huggingface.co/docs/transformers/en/model_doc/vitpose) · [PyTorch MPS](https://docs.pytorch.org/docs/2.14/notes/mps.html)
- SAM3 官方仓库包括 SAM3.1 发布说明，安装前提列出 CUDA GPU / CUDA 12.6+。M2 的 Metal GPU 不满足其官方 CUDA 路径；社区移植/模型转换需要单独验证，不能称为开箱即用的本地实时模型。[官方安装要求](https://github.com/facebookresearch/sam3#installation)

## 已实现的攀岩观察

| 类别 | 指标 | 定义及边界 |
| --- | --- | --- |
| 关键点 | 33 点坐标、可见度 | 原始图像归一化坐标，低可见度或画面外的点不参加计算 |
| 关节 | 左右肘、膝、髋、肩、踝，共 10 个角度 | 按视频宽高转换到像素平面；非三维关节角 |
| 重心观察代理 | 髋中心、肩髋几何中心 | 髋中心为双髋中点；几何中心为双肩中点与双髋中点的中点。没有质量权重，不是身体质量中心 |
| 身体位置 | 髋相对双踝中点的横向偏移 | 用投影躯干长归一化，向原始画面右方为正；不构成支撑面/平衡判断 |
| 展开程度 | 手间距、脚间距 | 二维端点距离 / 投影躯干长 |
| 肢体形态 | 左右臂、腿伸展比例 | 端点直线距离 / 两段肢体长度之和，范围 0–1；不表示技术优劣 |
| 移动 | 中心速度、竖直速度、两秒横移范围及轨迹 | 仅固定机位开启；速度以投影躯干长/秒表达，不是 m/s；竖直向上为正 |
| 节奏 | 连续低位移时长、停顿候选 | 中心及双腕双踝必须可靠，0.25–0.5 秒基线的最大位移速度低于 0.12 躯干长/秒；持续 0.8 秒标为候选。阈值是观察启发式，未校准为教练判断 |
| 岩点 | 手动标记中心、四肢最近岩点 | 固定机位暂停后点击标点；腕/脚尖离点不超过 0.2 个投影躯干长时提示邻近。既不是 SAM 分割，也不确认真实接触 |
| 导出 | JSON / CSV | 包含模型、固定机位状态、上述指标和缺失值；JSON 另含岩点与轨迹。最近 1800 帧 |

所有几何距离采用原视频宽高纠正长宽比；投影躯干不足 10 像素不做归一化。恢复播放、拖动、回环、超过 0.5 秒的观测间隔或中心丢失会重置时间统计；暂停保留最后一帧的数据。手脚缺失时不输出停顿判断。所有标记在新输入/切换模型时清空；镜像只改变显示，不改变导出坐标。

## 需要更多输入或验证的项目

- **真实重心 / 重心到支撑面的距离**：需要人体分段质量模型、可靠三维姿态与场景标定；当前只显示明示的几何代理。
- **手脚承重比例、抓握力、摩擦余量**：需要力传感器或经过验证的动力学模型，姿态画面不能直接测量。
- **离墙距离、墙角、真实米制速度**：需要墙面/相机标定，或深度、双目等信息。
- **真实用点顺序、换点次数、旗式/落膝/动态动作识别**：需可靠岩点几何、时间事件与教练标注验证，当前不把二维邻近升级为这些结论。
- **难度、受伤风险、技术评分、疲劳判断**：无经过验证的评分模型，当前不生成分数。
- **移动机位**：当前实时页没有相机运动补偿。手持视频应关闭固定机位模式；原离线示例中的相机配准属于另一流程。

这份范围表用于后续逐项补充，并不声称已实现所有攀岩分析能力。

- `npm test`：14 项通过，覆盖长宽比、缩放/平移不变性、低可见度、单位、静止与手部移动区别、时间中断、岩点邻近及 CSV 字段。

- 原有摄像头生命周期、视频上传/拖动/循环、知识库回归：`npm run test:e2e` 已通过，浏览器脚本错误 0；摄像头使用模拟输入，不代表实体摄像头精度。
